## umami (1698 files; brain ₹2.51)

### Then: written from the work 800 to 900 commits ago (2026-03-04 to 2026-03-23), ₹0.07

- Umami is a privacy-focused web analytics platform whose own screens call it Umami, built around website analytics views, boards, links, pixels, teams and an admin console, with its own API client and MCP server packages.
- Privacy-focused web analytics app: Next.js dashboard, HTTP API, and CLI/MCP tooling. People use it to track website traffic and visitor behavior without third-party cookies, viewing attribution, breakdowns, funnels, goals, heatmaps and journeys per website, and to build shareable boards from those metrics. It runs as a Next.js app backed by Prisma and a database, exposing over a hundred API routes, with a separate @umami/api-client package and an @umami/mcp command-line server for programmatic access. Teams, links, pixels, session replays and an admin console round out the product.
- Website Analytics Views: Website detail pages and shared hooks for attribution, breakdown, funnels, goals, heatmaps, and journeys. (starts at src/components/hooks/index.ts)
- Query Layer: Database query modules, types, and hooks for Prisma and SQL data access. (starts at src/lib/constants.ts)
- Boards: Board creation, editing, and rendering with component registry and controls. (starts at src/lib/boards.ts)
- Teams Management: Team listing, settings, and member management pages and APIs. (starts at src/index.ts)
- Admin Console: Admin pages for users, teams, security, and websites. (starts at src/components/common/PageHeader.tsx)
- Links: Link tracking pages, edit forms, tables, and CRUD APIs. (starts at src/app/(main)/links/LinkProvider.tsx)
- Pixels: Pixel tracking pages, edit forms, tables, and CRUD APIs. (starts at src/app/(main)/pixels/PixelProvider.tsx)
- API Client and MCP: @umami/api-client and @umami/mcp packages exposing the API to code and to an MCP command-line server. (starts at packages/api-client/src/index.ts)
- How it flows: A visitor's browser hits the tracking script, which writes events through the API into the database via the Query Layer.
- How it flows: Website Analytics Views and Boards read from the Query Layer through hooks to render dashboards, funnels, and shareable boards.
- How it flows: Teams Management and the Admin Console gate access to websites, boards, links, and pixels, while the API Client and MCP packages call the same HTTP API from outside the app.
- How its course changed: It was a privacy-focused Google Analytics alternative with links, pixels, and metrics components; the latest work is pushing it toward richer website analytics views, boards, sharing, and team-gated features like session replays.

## desktop (142 files; brain ₹2.29)

### Then: written from the work 45 to 145 commits ago (2026-09-29 to 2026-10-12), ₹0.04

- Tailzu Desktop is the X0 Bot desktop voice dictation app: a hotkey records you, the X0 Bot backend cleans the text, and it is pasted where your cursor is, with a pill that splits apart while it listens.
- Electron desktop voice-dictation app with native helpers. You press a hotkey (or hold a key), talk, and the cleaned-up text is pasted wherever your cursor is; the app reuses the X0 Bot backend for the cleaning. Around that it has grown a compact pill that comes apart while it listens, a recorder, notes, live captions, and native helpers that read the field and screen around where you are writing, including on-device OCR for apps that hide their text. The README still calls it voice dictation and does not mention the pill, recorder or native helpers, which is where the recent work went.
- Pill: A compact capsule that splits into its ✕ and ✓ halves while it listens, for quick bot status and controls. (starts at pill.html)
- Recorder: Captures and refines session recordings. (starts at recorder.html)
- Notes: A notes page with a recorder for capturing session notes. (starts at notes.html)
- Overlay captions: An overlay showing live captions and listening status. (starts at overlay.html)
- Guide: A page explaining bot usage with listening and stop controls. (starts at guide.html)
- Live view: Streams session output through shared main and guest logic. (starts at liveViewMain.js)
- Native platform helpers: Swift and PowerShell helpers for UI automation, timezone, key handling and OCR on native platforms. (starts at native/fake-uia-helper.js)
- Runner execution and redaction: Runs commands in Docker or preview mode over a WebSocket protocol, with guards and redaction of sensitive output. (starts at runner/redact.js)
- How it flows: A hotkey starts the Recorder; the audio goes to the X0 Bot backend, comes back cleaned, and is pasted at the cursor.
- How it flows: While listening, the Pill splits into its ✕ and ✓ halves and the Overlay captions show live captions.
- How it flows: Native platform helpers read the field and screen around the cursor, including on-device OCR, and send the device time zone with each dictation.
- How its course changed: It was a hotkey-to-paste dictation client for the X0 Bot backend, and it is becoming a fuller desktop assistant with a splitting pill, recorder, notes, live captions and native screen-reading helpers.

## pocketbase (883 files; brain ₹3.72)

### Then: written from the work 110 to 210 commits ago (2026-06-04 to 2026-08-13), ₹0.04

- PocketBase is a single-binary Go backend — an embedded SQLite database, REST/realtime HTTP API, admin superuser UI, and JSVM plugin runtime — that ships as one executable you run yourself.
- Self-hosted backend-as-a-service: Go HTTP API server with embedded database and admin web UI. You run one Go binary that serves a REST and realtime API over an embedded SQLite database, and you administer everything — collections, records, auth providers, settings, logs, backups — through the bundled Superuser UI. The Go core (router, store, filesystem/blob drivers, field definitions) is extended by a JSVM plugin runtime and a Vite-built JavaScript admin UI, so schema, rules, and API preview docs are all edited in the browser.
- Router: HTTP router with route groups, events, error handling, and request unmarshalling, including file-buffered bodies. (starts at tools/router/buffer_with_file.go)
- Record CRUD and Database: Core database, app, and store logic plus record endpoints for fetching, updating, and deleting. (starts at tools/store/store.go)
- Collection Management: Collection models, imports, auth options, and record table sync with related API routes. (starts at examples/base/main.go)
- Field Definitions: Core field type definitions and validation for autodate, bool, date, editor, email, and file. (starts at ui/src/base/fieldSettings.js)
- Field Types and Settings: Field implementations and UI settings for file, password, autodate, and bool field types. (starts at ui/src/main.js)
- Authentication and Types: Auth providers, origin models, and shared type helpers for datetime, geo points, and Apple sign-in. (starts at tools/types/datetime.go)
- Filesystem and Blob Storage: Filesystem abstractions and blob storage drivers including S3 object operations. (starts at tools/filesystem/file.go)
- Records UI: Record list, preview, upsert, impersonate, and file picker components in the admin UI. (starts at ui/src/records/recordFilePickerModal.js)
- How it flows: A request hits the Router, is unmarshalled, and is dispatched to Record CRUD and Database or Collection Management, which read and write through the store and Filesystem and Blob Storage.
- How it flows: In the Superuser UI, Collections UI and Field Types and Settings edit schema and rules, Field Definitions validates them, and API Preview Docs renders the resulting request examples.
- How it flows: Records UI and Logs UI read from the same API to list, preview, and impersonate records and to chart and inspect logs.
- How its course changed: It was a Go backend with an admin UI; it is becoming a more self-documenting and observable one, with API preview docs, a logs viewer, and filesystem writer helpers added in the latest work.
