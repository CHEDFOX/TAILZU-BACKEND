# The project's overview, with real models (2026-11-01)

`e2e/overview-real.ts`: each project's brain built as when a person connects it (real models), its overview as the project card shows it;
then the owner says it is changing course, and the overview tuned from that. The overview call costs ₹0.02 to ₹0.05; a tune ₹0.05.

How it stays true (src/code/project/overview.ts): every build compares the project with what the overview was written from (the kinds of app
the code shows, the stack, what the README says, the owner's words, the parts and their sizes, where the latest work is) and scores the drift,
for nothing. Small moves add up across builds; at a score of 1 it is tuned, given the overview as it was and what moved, at most once in six
hours. The owner's new words tune it at once. The overview it replaces is kept.

### First read

- A self-hosted backend server with a web admin UI and CLI. PocketBase is a backend-as-a-service that gives you a database, REST-ish HTTP APIs, authentication, file storage and an admin dashboard in a single Go binary. It is for developers who want to run their own backend without assembling many separate services. The README points people at official SDK clients as the easiest way to talk to its Web APIs.
- HTTP API and router: Serves the REST routes for records, collections, auth and settings, handling errors and request parsing. (starts at tools/router/buffer_with_file.go)
- Database and record core: Owns the app, database connection and store logic behind record CRUD and auth email changes. (starts at tools/store/store.go)
- Collections and records: Defines collection models, import, query and record table sync, plus the record CRUD endpoints. (starts at examples/base/main.go)
- Authentication: Handles auth providers, origins and token validation for Apple, OAuth and similar flows. (starts at tools/types/datetime.go)
- Filesystem and blob storage: Abstracts files and blobs with an S3 driver, readers, writers and bucket handling.
- Superuser admin UI: The Vite-built web interface for managing collections, records, settings, logs and API previews. (starts at ui/src/main.js)
- CLI: The Cobra command-line entry point for running and operating the server. (starts at examples/base/main.go)
- How it flows: A client calls the HTTP API; the router dispatches to the record, collection or auth handlers, which read and write through the database core.
- How it flows: In the admin UI, a superuser edits collections, records or settings; the UI calls the same HTTP API, which persists changes through the database core.
- How it flows: File uploads and downloads pass through the record handlers into the filesystem and blob storage layer, which may be local or S3.
